# Understanding Embeddings & Cosine Similarity

A deep dive into why embeddings are the mathematical backbone of semantic search in RAG applications.

---

## 1. The Core Problem: Exact Match vs. Semantic Meaning

Keyword retrieval evaluates string equality. It fails when terms have identical meaning but different vocabulary.

```text
Query: "Where is Nagarro based?"
Chunk: "The headquarters are in Germany."

Keyword Match: 0 matches (Score = 0.0) -> Retrieval Fails
```

Humans understand that **"based"** and **"headquarters"** express the same core concept. Embeddings bridge this gap by encoding **meaning into mathematics**.

---

## 2. What Is an Embedding?

An **embedding** is a dense numerical vector (an ordered array of floating-point numbers) representing the semantic meaning of a text segment:

$$\vec{v} = [v_1, v_2, v_3, \dots, v_d]$$

- Common vector dimensions: `384`, `768` (e.g. `nomic-embed-text`), `1536` (e.g. OpenAI `text-embedding-3-small`).
- Semantically similar texts produce vectors that point in nearly the same geometric direction in high-dimensional space.

```text
"Headquarters in Germany" ──► [ 0.12,  0.44,  0.77, ... ]
"Based in Germany"        ──► [ 0.15,  0.42,  0.79, ... ]  (Very close vectors)
"Recipe for chocolate"    ──► [-0.85,  0.11, -0.43, ... ]  (Distant vector)
```

---

## 3. Cosine Similarity

Cosine similarity measures the cosine of the angle $\theta$ between two vectors:

$$\text{Cosine Similarity}(\vec{A}, \vec{B}) = \frac{\vec{A} \cdot \vec{B}}{\|\vec{A}\| \|\vec{B}\|} = \frac{\sum_{i=1}^{n} A_i B_i}{\sqrt{\sum_{i=1}^{n} A_i^2} \sqrt{\sum_{i=1}^{n} B_i^2}}$$

| Metric Range | Meaning |
|---|---|
| **$1.0$** | Identical direction / perfect semantic similarity |
| **$0.0$** | Orthogonal vectors / unrelated content |
| **$-1.0$** | Exact opposite direction |

### Why Direction (Cosine) Over Euclidean Distance?
Cosine similarity measures the angle between vectors regardless of magnitude (length), making it robust to variations in sentence length.

---

## 4. Ingestion vs. Query Retrieval Flow

### Ingestion Flow
```text
Document ──► Chunking ──► Embedding Model ──► Vectors ──► Vector Store (Qdrant)
```

### Retrieval Flow
```text
User Question ──► Embedding Model ──► Query Vector ──► Cosine / Dot Product ──► Top-K Chunks
```

---

## 5. Embedding Model vs. Chat Model

| Characteristic | Embedding Model (e.g. `nomic-embed-text`) | Chat Model (e.g. `gemma2:2b`, `llama3`) |
|---|---|---|
| **Input** | Plain text string | Structured conversation prompt & context |
| **Output** | High-dimensional dense vector (`float[]`) | Generated text tokens |
| **Purpose** | Semantic vectorization & similarity ranking | Natural language generation & synthesis |
