First Principle: Computers Understand Numbers, Not Meaning

Computers ultimately work with numbers.

For example:

Dog


To us:

Animal
Pet
Friendly


To a computer:

D
o
g


just characters.

The computer has no idea what a dog actually is.

So we need a way to convert meaning into mathematics.

What Is An Embedding?

The simplest definition:

An embedding is a numerical representation of meaning.

Example:

Dog


might become:

[0.23, -0.44, 0.91, ...]


and

Puppy


might become:

[0.27, -0.41, 0.95, ...]


Notice:

Dog
Puppy


have similar meanings.

Therefore their vectors are located close to each other.

Important Mindset Change

An embedding is NOT:

Keyword encoding


An embedding IS:

Meaning encoding


For example:

Headquarters


might become:

[0.12, 0.44, 0.77, ...]

Based


might become:

[0.15, 0.42, 0.79, ...]


Different words.

Similar meaning.

Vectors end up close together.

What Is A Vector?

A vector is simply an ordered list of numbers.

Example:

[1, 2]


That's a vector.

Example:

[1, 2, 3, 4]


Also a vector.

Example:

[0.12, 0.54, -0.88, 0.22]


Also a vector.

For embeddings:

Typical sizes are:

384 dimensions
768 dimensions
1024 dimensions
1536 dimensions
3072 dimensions


Example:

[0.13, 0.88, -0.12, 0.44, ... 768 values]

Why So Many Numbers?

Because meaning is complex.

Think of human description.

If I describe a person:

Height
Weight
Age
City
Profession


Those are dimensions.

Similarly, embeddings represent meaning across hundreds of dimensions.

Not:

Dimension 1 = dogness
Dimension 2 = friendliness


It's much more abstract than that.

The model learns these dimensions automatically.

What Happens During Embedding Generation?

We pass text to an embedding model.

Example:

"The headquarters are in Germany"


↓

Embedding Model

↓

[
  0.15,
  -0.93,
  0.67,
  ...
]


That array is the embedding.

What Gets Stored?

Not the question.

Not the answer.

Not AI magic.

Just:

DocumentChunk
{
    Content = "The headquarters are in Germany",

    Embedding =
    [
        0.15,
        -0.93,
        ...
    ]
}


That's it.

What Is Cosine Similarity?

This is the heart of vector search.

Question:

How similar are two vectors?

Imagine 2D space.

Vector A:

→


Vector B:

→


Almost same direction.

Similarity:

1.0


Very similar.

Vector A:

→


Vector B:

↑


90 degrees.

Similarity:

0


Unrelated.

Vector A:

→


Vector B:

←


Opposite direction.

Similarity:

-1


Completely opposite.

Real embeddings use:

384+
dimensions


instead of:

2 dimensions


but the idea is identical.

Why Use Direction Instead Of Distance?

Good question.

Suppose:

[1, 2]


and

[10, 20]


Different lengths.

Same direction.

Meaning is mostly preserved.

Cosine similarity focuses on:

Direction


instead of:

Magnitude


which often works better for semantic search.
