# RAG From First Principles — Learning Path

Building a production-grade Retrieval-Augmented Generation (RAG) system from scratch by understanding core principles before adopting heavy frameworks.

---

## What is RAG?

**RAG = Retrieval-Augmented Generation**

### Without RAG
```text
User ──► LLM ──► Answer (Only knows training data; may hallucinate on private context)
```

### With RAG
```text
User Question ──► Retriever ──► Relevant Context ──► LLM ──► Grounded Answer
```
The LLM acts as a **reasoning engine**, using your private knowledge rather than relying solely on parametric memory.

---

## High-Level Pipeline

```text
               [ Documents ]
                     │
                     ▼
             [ Text Extraction ]
                     │
                     ▼
                [ Chunking ]
                     │
                     ▼
             [ Embedding Model ]
                     │
                     ▼
               [ Vector Store ]
                     │
 User Query ─────────┼─────────► [ Similarity Search ]
                                         │
                                         ▼
                               [ Top Matching Chunks ]
                                         │
                                         ▼
                                       [ LLM ]
                                         │
                                         ▼
                                 [ Final Response ]
```

## Evolutionary Stages in This Repository

### Stage 1: Simplest RAG (Keyword Retrieval)
- Chunk plain text into sentences or paragraphs.
- Execute simple keyword lookups.
- Feed retrieved text into an LLM prompt.
- *Limitation:* Vocabulary mismatch (e.g. query "headquarters" fails to match "based in").

### Stage 2: Semantic Embeddings & Vectors
- Transform text into dense numerical vectors representing semantic meaning.
- Compute **Cosine Similarity** between query vectors and chunk vectors.
- Semantic matching bridges synonym and phrasing gaps.

### Stage 3: In-Memory to Persistent Vector Database
- Transition from `List<DocumentChunk>` in memory to persistent vector databases (**Qdrant**).
- Support persistence, fast indexing (HNSW), and metadata filtering.

### Stage 4: Multi-Format Documents & Chunking Strategies
- Extract text from PDFs using `PdfPig`.
- Implement sliding-window chunking (1000 characters with 200 character overlap) to preserve boundary context.

### Stage 5: Conversational Memory & Streaming
- Store multi-turn conversation history (sliding 4-turn window).
- Provide real-time token streaming via Server-Sent Events (SSE).

### Stage 6: Multi-Provider AI Architecture
- Decouple AI models from business logic; switch seamlessly between local models (Ollama) and cloud APIs (Groq).

### Stage 7: Evaluation & Benchmarking
- Measure system performance with groundedness, relevance, and accuracy metrics across a 12-question test suite.
