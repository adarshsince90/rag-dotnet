# Recommended Roadmap & Sprint Architecture

## Sprint 00: Foundation
**Goal:** Create a clean, scalable skeleton.

**Features:** Architecture & project structure setup following Clean Architecture and Dependency Inversion.

```text
RagDemo/
├── Api/              # HTTP endpoints, middleware, DI wiring
├── Application/      # Orchestration, services, prompts, pipelines
├── Domain/           # Core entities, contracts/interfaces
├── Infrastructure/   # External integrations (Ollama, Groq, Qdrant, PdfPig)
└── Cli/              # Interactive console terminal client
```

### Domain Layer (Contracts)
```csharp
public interface IDocumentExtractor { ... }
public interface IChunkingStrategy { ... }
public interface IRetriever { ... }
public interface IChatCompletionService { ... }
public interface IEmbeddingGenerator { ... }
public interface IVectorStore { ... }
public interface IConversationMemory { ... }
```

### Infrastructure Layer (Implementations)
```csharp
public class PdfDocumentExtractor : IDocumentExtractor { ... }
public class CharacterChunkingStrategy : IChunkingStrategy { ... }
public class KeywordRetriever : IRetriever { ... }
public class VectorRetriever : IRetriever { ... }
```

> **Key Benefit:** When replacing `KeywordRetriever` with `VectorRetriever`, no upstream business logic breaks.

## Sprint 01: Keyword Retrieval
**Goal:** Understand retrieval from first principles without AI, embeddings, or vector databases.

**Features:**
- Load text documents.
- Chunk text by delimiters/sentences.
- Execute keyword-based similarity search (TF-IDF).
- Return matching chunks.

```text
Question ──► Keyword Search ──► Chunk ──► API Response
```

**Example:**
- `POST /ask` with `"Where is Nagarro headquartered?"`
- Returns: `{ "chunk": "Headquarters are in Germany" }`

---

## Sprint 02: Ranking & Diagnostics
**Goal:** Introduce ranking algorithms, score thresholds, and detailed retrieval diagnostics.

**Features:**
- Top-K result scoring and ranking.
- Retrieval diagnostics (score gaps, latency, match count).
- `RetrievalResultProcessor` component.

---

## Sprint 03: Embeddings & Semantic Retrieval
**Goal:** Replace keyword matching with mathematical semantic similarity.

**Features:**
- Embedding generation (converting text to 768-dimensional dense vectors via `nomic-embed-text`).
- Cosine similarity computation.
- In-memory vector storage (`VectorRetrieverInMemory`).

```text
Chunk    ──► Embedding Model ──► Vector ──► In-Memory Store
Question ──► Embedding Model ──► Vector ──► Cosine Similarity ──► Top Matches
```

*Query like "Where is Nagarro based?" matches "Headquarters are in Germany" even with zero overlapping words.*

---

## Sprint 04: Generation & LLM Integration
**Goal:** Connect an LLM to generate natural answers using retrieved chunks.

**Features:**
- Local LLM via Ollama (`gemma2:2b`).
- Grounded prompt construction (`RagPromptBuilder`) to reduce hallucinations.
- `QuestionAnsweringService` orchestrator.

```text
Question ──► Semantic Retrieval ──► Grounded Prompt ──► LLM ──► Grounded Answer
```

---

## Sprint 05A: Chunking Strategy Experiments
**Goal:** Experiment with chunk sizing, token limits, and boundary overlaps.

**Features:**
- `CharacterChunkingStrategy` (1000 characters with 200-character overlap).
- Empirical comparison of chunk boundaries in `docs/experiments/chunking-lab.md`.

---

## Sprint 05B: PDF Document Ingestion
**Goal:** Ingest raw multi-page PDF documents.

**Features:**
- Extract text from PDFs using `PdfPig`.
- `PdfDocumentExtractor` & `PdfChunkProvider`.
- Maintain provenance metadata (source document filename, page number).

```text
Raw PDFs ──► PdfPig Extraction ──► Clean Text ──► Overlapping Chunks ──► Embeddings
```

---

## Sprint 06: Persistent Vector Storage (Qdrant)
**Goal:** Decouple vector persistence from application memory and eliminate startup re-indexing.

**Features:**
- Dockerized `Qdrant` vector database.
- `IVectorStore` abstraction and `QdrantVectorStore` implementation.
- Fast similarity search with HNSW indexing and payload metadata storage.

---

## Sprint 07A: Streaming Responses
**Goal:** Stream generated tokens in real-time to eliminate perceived latency.

**Features:**
- Server-Sent Events (SSE) protocol.
- `IAsyncEnumerable<string>` streaming pipelines through `IChatCompletionService`.
- Streaming endpoints (`/ask/stream`, `/conversation/stream`).

---

## Sprint 07B: Conversational Memory
**Goal:** Maintain multi-turn chat context across queries.

**Features:**
- Rolling 4-turn conversation sliding window (`IConversationMemory`).
- `ConversationQueryBuilder` to formulate context-aware retrieval queries.
- `ConversationQuestionAnsweringService` orchestration.

---

## Sprint 08: Evaluation Framework
**Goal:** Measure retrieval and generation quality objectively.

**Features:**
- Automated 12-question benchmark suite (`data/evaluation/`).
- `EvaluationService` scoring across:
  - **Relevance**: Accuracy of retrieved chunk IDs.
  - **Accuracy & Completeness**: Correctness against ground truth.
  - **Groundedness**: Faithfulness to context.

---

## Sprint 09A: Production Hardening
**Goal:** Enhance resilience, configuration management, and diagnostics logging.

**Features:**
- Comprehensive diagnostic metrics catalogue (`DiagnosticMetricsCatalogue.md`).
- Centralized exception handling, clean DI extensions (`ServiceCollectionExtensions.cs`).

---

## Sprint 10: Interactive Console Client
**Goal:** Developer-friendly interactive CLI terminal application.

**Features:**
- `RagDemo.Cli` project with interactive prompt loops.
- Real-time token streaming in the terminal.
- Commands: `/new` (reset conversation), `/exit`.

---

## Sprint 11: Multi-Provider AI Architecture
**Goal:** Seamlessly switch between local models and high-speed cloud providers.

**Features:**
- Factory / Strategy provider resolution via configuration.
- Local provider: **Ollama** (`gemma2:2b` + `nomic-embed-text`).
- Cloud provider: **Groq** (`llama-3.3-70b-versatile` / `llama3-8b-8192`) via `GroqChatCompletionService`.
- Secure API key management via .NET User Secrets.

---

## Sprint 12: Browser Chat UI
**Goal:** Modern, responsive browser user interface.

**Features:**
- Static chat UI served via ASP.NET Core `wwwroot` (`/index.html`).
- Real-time SSE streaming consumption in JavaScript.
- API interactive docs via Scalar (`/scalar`).

---

## SOLID-Focused Design Rules

1. **Rule 1 — LLM Independence**: Never call Ollama/Groq directly from application services. Use `IChatCompletionService`.
2. **Rule 2 — Vector Store Decoupling**: Never access vector storage directly. Use `IVectorStore`.
3. **Rule 3 — Extraction Isolation**: Never tightly couple to PDF libraries. Use `IDocumentExtractor`.
4. **Rule 4 — Stateless Presentation**: Never store conversation state inside controllers/endpoints. Use `IConversationMemory`.
5. **Rule 5 — Centralized Prompt Templates**: Keep prompt templates unified under `RagPromptBuilder`, not scattered across services.
